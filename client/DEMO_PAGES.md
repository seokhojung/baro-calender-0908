# 데모 페이지 가이드

바로캘린더 프로젝트의 개발 환경 전용 데모 페이지들에 대한 가이드입니다.

## 🎯 데모 페이지 목록

### 1. `/demo` - 디자인 시스템 데모
**목적**: ShadCN UI 컴포넌트와 디자인 토큰 검증
**사용 시기**:
- 새로운 UI 컴포넌트 개발 시
- 디자인 시스템 일관성 확인 시
- 테마 시스템 테스트 시

**주요 기능**:
- 8색상 프로젝트 팔레트 확인
- 다크/라이트 테마 전환 테스트
- 타이포그래피 스케일 검증
- 스페이싱 시스템 확인
- 모든 기본 UI 컴포넌트 테스트

### 2. `/responsive-demo` - 반응형 및 접근성 테스트
**목적**: 모바일 최적화 및 접근성 기능 검증
**사용 시기**:
- 반응형 레이아웃 개발 시
- 접근성 기능 구현 시
- 성능 최적화 확인 시

**주요 기능**:
- 디바이스별 반응형 테스트
- 터치 최적화 버튼 테스트
- 키보드 네비게이션 확인
- 성능 메트릭 모니터링
- 접근성 기능 테스트

### 3. `/layout-demo` - 레이아웃 컴포넌트 테스트
**목적**: 레이아웃 블록 컴포넌트 검증
**사용 시기**:
- 대시보드 레이아웃 개발 시
- 사이드바 컴포넌트 수정 시
- 전체 레이아웃 구조 확인 시

**주요 기능**:
- Dashboard 블록 테스트
- Sidebar 블록 테스트
- CalendarBlock 테스트
- 통합 레이아웃 확인

## 🔒 접근 제한

### 개발 환경
- ✅ 모든 데모 페이지 접근 가능
- ✅ 페이지 상단에 "개발 환경 전용" 배지 표시

### 프로덕션 환경
- ❌ 데모 페이지 접근 차단 (자동으로 메인 페이지로 리다이렉트)
- ❌ 네비게이션에서 데모 링크 숨김

## 🚀 사용 방법

1. **개발 서버 실행**
   ```bash
   npm run dev
   ```

2. **데모 페이지 접속**
   - http://localhost:3000/demo
   - http://localhost:3000/responsive-demo
   - http://localhost:3000/layout-demo

3. **프로덕션 빌드 테스트**
   ```bash
   npm run build
   npm start
   ```
   프로덕션 모드에서는 데모 페이지가 차단됩니다.

## 🛠️ 개발 팁

### 새로운 컴포넌트 테스트
1. `/demo` 페이지에서 기본 스타일 확인
2. `/responsive-demo`에서 모바일 호환성 테스트
3. 필요시 `/layout-demo`에 새 레이아웃 추가

### 성능 테스트
- `/responsive-demo`의 성능 모니터 기능 활용
- 디바이스별 성능 메트릭 확인
- 메모리 사용량 및 렌더링 시간 모니터링

### 접근성 검증
- `/responsive-demo`의 키보드 네비게이션 테스트
- 스크린 리더 호환성 확인
- 고대비 모드 테스트

## 📁 관련 파일

```
client/src/
├── app/
│   ├── demo/page.tsx                 # 디자인 시스템 데모
│   ├── responsive-demo/page.tsx      # 반응형 테스트
│   └── layout-demo/page.tsx          # 레이아웃 테스트
├── middleware.ts                     # 프로덕션 접근 제한
└── components/
    ├── ui/                          # 기본 UI 컴포넌트들
    └── layout/                      # 레이아웃 컴포넌트들
```

## ⚠️ 주의사항

1. **프로덕션 배포 전 확인**: 데모 페이지가 실제 서비스에 노출되지 않도록 middleware 설정 확인
2. **성능 영향**: 데모 페이지의 무거운 컴포넌트가 메인 번들에 영향을 주지 않도록 lazy loading 고려
3. **보안**: 개발 전용 정보가 데모 페이지를 통해 노출되지 않도록 주의
